Struct Vec

A contiguous growable array type, written as Vec<T>, short for “vector”.

Capacity and reallocation

The capacity of a vector is the amount of space allocated for any future elements that will be added onto the vector. This is not to be confused with the length of a vector, which specifies the number of actual elements within the vector. 

let mut vec = Vec::with_capacity(10);
assert_eq!(vec.len(), 0);
assert!(vec.capacity() >= 10);

What it does

Ingests documentation sites. ReadTheDocs and Sphinx, rustdoc, mdBook, MkDocs, Docusaurus, plain HTML, and man pages. Tome classifies a site from its homepage and picks the right scraper, or asks when it is not sure — an unsure answer costs one dialog, a confidently wrong one fills your library with mis-parsed pages that look fine until you read them.

0.9922 detection accuracy over 128 homepages, zero confident errors · P2-014

Searches across everything. ⌘K opens search with snippets and scoping; ⌘F finds within the open page. Typing a function's call syntax works — os.cpus(), Vec::new, [features] — and a term prefixed with @ finds the pages that declare a symbol rather than the hundreds that mention it.

0.9082 recall@3 over 339 documents, 207 queries · target ≥ 0.90 · S2-12

Stays fast as the library grows. Search is measured against the same queries the relevance harness uses, not generated ones — a synthetic query has whatever selectivity its author gave it.

158 µs P95 against a 100 ms budget · index 224 MB per 100 000 pages · SPIKE-003

Reads offline, really. Assets are fetched once and rewritten to local content-addressed paths; the reader re-checks that at render, and its content-security policy allows only the tome: protocol. Opening a page cannot touch the network, because there is nothing left in it that points outward.

Your agent reads it too

Tome ships an MCP server over stdio. Claude Code — or anything else that speaks MCP — searches your library, opens pages, and looks up symbols, in the versions you actually have pinned rather than whatever it remembers. 

$ tome mcp

The tools are read-only, deliberately. Documentation Tome ingests is untrusted text that agents read, so a prompt injection in a scraped page must not be able to reach a write. Anything that changes your library is a command you type.

Where it stands

Everything works except being installable. The DMG builds and the cask is written; no tag has been cut.

Works today

  • Fetch, normalize, sanitize, localize, index
  • The reader: offline, typeset, outline, history
  • Search: ⌘K, ⌘F, typo tolerance, symbols
  • Man pages and platform detection
  • CLI, MCP server, local HTTP API
  • A Claude Code plugin and a source registry
  • First-run onboarding, preferences, a menu bar item
  • A DMG carrying the app and the CLI from one build

Does not exist

  • Bookmarks and annotations
  • Cross-device sync (designed, deferred)
  • A signed or notarized build (deferred)
  • A published release — the pipeline exists, no tag

Not published. npm run tauri build produces a DMG whose Tome.app contains the tome CLI, and a script verifies the two are one build. What is missing is a tag and the tap repository. Signing is deferred, so the release will ship unsigned and Gatekeeper needs one xattr command on first launch. Until a tag is cut, building it yourself is the way.

Commitments

These are constraints, not aspirations. Where the plan violated one, the plan changed.

No telemetry. None. No analytics, no crash reporting, no phone-home, not even opt-in. The cost is real and worth stating: there is no usage data, so product direction comes from conversations rather than dashboards.

0 endpoints any metric expressed as “% of users” is therefore unmeasurable, and none is claimed

A good citizen on the web. Tome downloads documentation other people wrote. It obeys robots.txt — not overridable for registry-shipped configurations — rate-limits per host, identifies itself honestly, honours Retry-After, links back to the origin, and never redistributes.

Local-first. Your documentation and your reading live on your machine. Sync, when it exists, carries bookmarks only — never content, and never through a server of ours.
