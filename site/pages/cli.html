Command reference

Everything tome does. Anything not on this page does not exist — the CLI surface is specified, and commands used to enter this project as examples in unrelated documents.

Every command takes --json. Success is one JSON document on stdout with a stable shape per command and every key present even when empty, so jq needs no special cases. Errors are JSON on stderr — {"error": {"message": …}} — stdout stays empty, and the exit code is non-zero.

stdout is data progress, prompts and diagnostics all go to stderr, always. A progress line in a piped JSON stream is a parse error at the other end.

Sources

tome add <url>

Detect the platform, write a configuration, pull. Interactive unless --yes.

--yes, -y Skip confirmation. Required with --json or a non-terminal stdin, and checked before any network traffic.
--name <id> Set the source id. Derived from the URL otherwise.
--category <name> Library category. Defaults to Uncategorized.
--insecure Permit http and private hosts, for a server you own. Written into the config as fetch.allow_insecure.

Duplicates are refused by id and by URL, so the same site cannot be added twice under two spellings. The YAML it writes is round-tripped through the real parser before the initial pull: add cannot write a config pull would reject.

tome pull [source]

--all Every configured source.
--due With --all: only sources their sync strategy says are due, naming what it skipped and why.
--max-pages <n> Cap the crawl, overriding the config. Only ever tightens. For health checks.

Indexing happens as it goes, and only pages whose content hash changed are rewritten. The report names what went wrong — failed pages, un-localized assets, whether the page cap was hit.

A pull also removes pages the site no longer has, and says how many. That happens only when the crawl finished cleanly: no page cap, no ambiguous errors, and at least one page found. Any doubt at all and nothing is deleted — the next clean run catches up.

404 ≠ error a page that is gone is the evidence pruning runs on · a 5xx or a timeout is a page that could not be read, which is evidence of nothing

tome list

Sources with page counts, categories and sync recency. --category <name> filters, reading each config file rather than the database, because a source that has never been pulled still has a category.

tome remove <source>

Deletes the source's search index entries, database rows, cached content, and — last — its config file. Last, so a partial failure leaves a state remove can be run against again. Confirmation defaults to No; --yes skips it.

four places skipping the index would leave results pointing at pages that no longer exist

Reading

tome search <query>

--scope <source-id> One source only.
--limit <n> Results to return. Default 10.

Prefix a term with @ to search declared symbols only: tome search "@with_capacity" returns the pages that declare it rather than every page that mentions it. Under --json, results carry symbol_kind (null for prose pages) and corrections come back as a suggestions array — both always present.

tome status

Version, bundle id, and where the library lives. --show-token prints the API bearer token, creating one if none exists — the one place it is ever printed.

Programmable surfaces

tome mcp

The MCP server, over stdio. A client spawns it; there is no port and nothing to leave running. Setup is here.

--http exists in the help and is not implemented, by choice: no client Tome targets needs it, and an HTTP MCP endpoint has exactly the browser-reachability problem the local API spends its whole middleware stack on.

stdio only MCP defines stdio and Streamable HTTP. There is no Unix-socket transport — an earlier design specified one, and no client could have connected.

tome serve

The local HTTP API, on 127.0.0.1:7431. Off unless you run this.

--port <n> Default 7431. 0 picks an ephemeral port, printed to stderr.
--bind <addr> Default 127.0.0.1. Anything else logs a warning.
--allow-origin <origin> Let a browser origin read responses. Repeatable. * is refused before the server starts.

Every request needs Authorization: Bearer <token> except GET /api/v1/status — including on loopback. Loopback is not a trust boundary: every process on your machine and every page in your browser can originate a loopback request.

no bypass the token is 256 bits, kept in the Keychain, compared in constant time, and the server holds only its hash after startup

No CORS headers are emitted by default, Host and Origin are validated against DNS rebinding, and a request carrying a non-allowlisted Origin is refused outright rather than merely denied headers — absence of CORS hides the response, refusal also stops the request having effects.

tome config rotate-token

Replace the API token. A running server keeps its startup token until restarted, and the command says so.

tome config forget-token

Delete the API token from the Keychain. This exists because of uninstall: brew uninstall --zap removes files, and the Keychain is not a file, so without it the one secret Tome creates outlives the uninstall. Idempotent — on a machine that never ran the server it says there was nothing to remove.

Diagnostics

tome debug is hidden from the top-level help. Nothing here belongs to an ordinary day, and a debug command in the main list invites people to reach for it before the command that would have worked. Troubleshooting is the walkthrough.

tome debug check

Reports; never repairs — a check that fixes things cannot be run twice to see whether the fix worked. Library writable, database opens, every source configuration parses, index opens, and the index and the database agree on every source’s page count. Exits non-zero when something is wrong. An empty library is healthy, not a fault.

tome debug rebuild-index

Discards the search index and rebuilds it from the pages already on disk. No network. The database, the configurations and the cached content are untouched.

tome debug report

A redacted diagnostic bundle on stdout, to paste into an issue. No page paths, no search queries, no note text, $HOME rewritten to ~. There is no telemetry and there will not be, so this is the only path from a broken machine to something a maintainer can read.

--lines <n> How many log lines to include. Default 50.
